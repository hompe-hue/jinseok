# 받은 원본 프로젝트의 저장값·내장 입력표 감사

`Bolt_Model_Check.proj`를 읽기 전용으로 확인했다. 원본 ZIP CRC는 통과했고 XML은 실행/역직렬화하지 않고 안전한 데이터 파서로 읽었다. 원본을 수정하지 않았다. 프로젝트 SHA256과 식별 ID는 audit.json에 저장했다.

## 확인한 현재 저장값

| 항목 | 프로젝트 내부 값 | 기존 61905061 조건과 대조 |
|---|---:|---|
| Module 1/2 초기 SOC | 둘 다 62.836170% | 일치 |
| Module 1/2 배터리 온도 | 둘 다 26°C | 일치 |
| 셀 용량 | 각각 56 Ah, 48S3P | 팩 168 Ah 가정과 일치 |
| 보조부하 | 0.40 kW | 일치 |
| Final Drive 기어비/효율 | 7.05 / 1.0 | 현재 기록과 일치 |
| 저장된 종료시간 | 1489.898579121초 | 일치 |
| 내장 주행 프로파일 | 1491점, 말단 1489.898579121초 | 원본 준비 속도와 최대 차이 5e−13 km/h |

두 모듈의 OCV와 충방전 R 표 총 6개는 기존 입력 DAT와 숫자가 정확히 동일하다. OCV SOC 축은 %이고 R SOC 축은 0–1 분율이다. 두 모듈은 모두 RC와 충방전 분리 OCV가 비활성인 저장 설정이다. 각 표의 multiplier는 1이다. 저장된 표는 25°C이며 정의한 배터리 온도 26°C를 별도 온도특성 검증으로 간주하지 않는다.

모터의 선택 손실 형식은 power_loss이며 Q1과 Q4가 선택돼 있다. 내장 Q1 표 153점과 Q4 표 128점을 추출했다. 기존 17×17 손실표의 대응 운전점과 대조하면 최대 차이는 각각 1.07e−14/7.11e−15 kW다. 따라서 다른 파일이나 잘못된 수치표를 적용했다고 볼 증거는 없다. 이 점별 일치는 실행 시 보간·외삽의 모든 동작이나 실차 효율을 검증한 것은 아니다.

## DAT 추가 요청 여부

검사한 주행 프로파일·배터리 OCV/R·모터 손실표는 프로젝트 안에 숫자로 내장돼 있다. 디코딩된 문자열에서 `.dat` 파일명 참조는 발견되지 않았다. **이번에 확인한 입력표의 대조를 위해 별도 DAT 첨부는 필요 없다.** 다른 종류의 외부 자원이나 플러그인이 전혀 없다는 포괄적인 실행 가능 판정은 아니다.

## 케이스 전환 시 주의할 실제 저장 구조

Cycle Run 케이스 집합의 저장된 Parameter group 1에는 Profile만 변동 항목으로 등록되어 있다. ANL61905061은 내장 프로파일 element37675에 연결된다. **케이스 이름만 변경한다고 초기 SOC·배터리 온도·종료시간까지 이전 시험 값으로 돌아간다고 볼 수 없다.** 앞으로 재실행을 요청할 때는 프로파일과 함께 시험별 초기값/종료시간을 다시 명시해야 한다. 현재 저장값은 61905061과 일치하므로 이 이유로 재실행할 필요는 없다.

## 판정과 다음 시작점

핵심 저장값과 내장 입력표 대조 완료. 현재 받은 원본에서 배터리 표의 단위/숫자나 다른 모터 맵을 적용한 오류는 확인되지 않았다. 단순 입력 수정으로 +8~9% 차이를 해소할 근거는 아직 없다. 기존 실차 검증 미달 판정은 유지한다.

다음은 내장 맵의 보간/외삽 설정과 실제 운전점의 경계 사용을 원본 기준으로 확인하는 후속 배치다. 특히 Q4의 128점 영역과 근제로 토크/속도 구간을 구분해 살핀다. 이 작업은 보유한 파일로 할 수 있으며 지금 사용자 추가 파일이나 시뮬레이션 요청은 없다. 전체 회로의 실행 검증이나 새 배터리 파라미터 식별을 이번 저장값 감사 완료에 섞지 않는다.
