# 067 종료시간9500초 진단 실행

실패한 실행에서는 CSV를 확보할 수 없다는 사용자 확인을 반영했다. 이번에는 소진 전에 정상 종료하여 원인 분석용 데이터를 저장한다. 기존067 전체10122.190356초 검증을 이 파일로 통과 처리하지 않는다.

## 실행1회

1. ZIP을 풀고 `C3_DIAG_ANL61905067_END9500.proj`를 연다.
2. `REEV_MBE → Cycle Run → ANL61905060`을 선택한다. 기존 Case 이름을 유지했으며 실제 내장 프로파일은067이다.
3. 상단 **End time =9500 s**를 확인하고 Run 한다. 초기 모델SOC는 기존 **81.7535907393%**, 배터리 온도24.5°C다. SOC를 추가로 올리지 않는다.
4. 정상 종료하면 기존과 같은 신호를 `battery_067_END9500.csv`, `velocity_067_END9500.csv`, `generator_067_END9500.csv`로 내보낸다. 저장한 실행 프로젝트와 solver log도 보관한다.
5. 다시 실패하면 같은 실행을 반복하지 말고 실패 시간과 Details 오류 원문을 전달한다. 이 환경에서는 CRUISE solver를 실행하지 못했으므로 정상 종료를 보장한 파일은 아니다.

## 변경 범위

원본 `C3_LIMITS_ANL61905067.proj`와 비교해 **활성 Task의 종료시간 값 하나만**10122.190356→9500초로 바꿨다. 초기SOC·용량·OCV/R·EDU·차량·제어식·회생/충방전 제한·Case/Pool 연결·전체 내장 프로파일은 같다. XML의 그 숫자 하나를 원래대로 복원했을 때 원본 XML과 완전히 일치함을 확인했다. ZIP의 XML 이외 모든 멤버도 원본과 같다.

기존 파일에서 직접 할 경우 Simulations 상단 End time을9500으로 변경하고 다른 이름으로 Save As한 뒤 실행해도 된다. 이번 수정본을 사용하면 수동 설정 변경이 필요 없다.

## 분석 목적

9500초는 이전 화면의 약9906초보다406초 빠르다. 같은 모델의 소진 직전 구간까지 전류·SOC 적분, 실측 대비 누적 전력/에너지, 속도 추종·브레이크, 기계출력/손실 및 DC 수지를 확인한다. SOC를 임의로 높여 실측과 다른 초기 조건을 만드는 대신 비교 가능한 구간의 데이터를 먼저 확보한다.

추종 대상은 기존067 속도 프로파일이며, 9500초에서 구동 중에 중단된다. 비교는 같은0–9500초(에너지·전압20–9500초) 측정 창에서만 하고 이후 정차/방전 종료까지의 거리·SOC·에너지로 외삽하여 통과시키지 않는다. 끝시간 조정은 원인을 해결한 보정이 아니라 진단용 실행 설정이다.

자동 비교 예: `python evaluate_C3_067_diagnostic.py --package . --test 61905067 --exports ./exports_067_END9500` . 출력은 진단 창의 기준 충족 여부이며 `full067_validation_complete=false`를 유지한다.
