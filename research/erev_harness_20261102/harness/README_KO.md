# BEV·EREV 연구 하네스 v1

지금까지의 검증 코드와 연구 기록을 공통 절차로 묶은 실행 도구다. 기존 연구 결과를 옮겨 등록했으며 새 시뮬레이션 결과를 만든 것이 아니다. 사용자 PC의 CRUISE M은 현재 수동 실행하고, 이 도구가 파일 접수·검사·수치 분석·상태 보고를 담당한다.

## 현재 작업을 이어가는 방법

사용자는 기존처럼 CRUISE M 결과 CSV를 보내면 된다. Python 설치나 하네스 실행은 필수 작업이 아니다. 현재 필요한 새 결과는 **SMCT_DENSE_SAVED10.proj의 실제 세밀 출력 한 건**이다. `assets/projects/SMCT_DENSE_SAVED10.proj`가 포함돼 있다. 원래 물리 입력과 solver 설정은 그대로이며 결과 저장 stride만100→10으로 바꾼 준비본이다. 실제 CSV 간격0.1초 이하 여부를 결과로 확인한다. 1초 결과를 보간해서 표본을 늘리면 안 된다.

R0를 제공한 파일 그대로 실행했다는2026-11-02 사용자 확인을 기록했다. 같은 확인을 위해 R0를 다시 실행하거나 제출할 필요 없다. 이전 결과 저장 실패 로그와 후속 정상 완료 확인은 별도 근거다.

## 공통 명령

Python3.10 이상과 requirements.txt의 패키지가 있는 환경에서 이 폴더를 기준으로 실행한다.

```text
python research.py status
python research.py resume
python research.py verify
python research.py refresh
```

- status: 시험별 자료 상태 확인
- resume: 현재 필요한 다음 작업 한 가지 확인
- verify: 등록한 모델·기준자료·접수자료의 해시 검사
- refresh: 접수된 CSV 재검토 → 오프라인 분석5개 실행 또는 동일 버전 결과 재사용 → 현재 보고 갱신

결과 보고는 `reports/CURRENT_KO.md`, 구조화된 상태는 `reports/state.json`에 생성된다. `refresh`는 CRUISE M을 실행하지 않는다.

## 새 CSV 접수 예

파일명은 자유롭지만 battery/velocity/generator 역할은 명시한다. 경로에 공백이 있으면 따옴표로 감싼다.

```text
python research.py ingest --run SMCT_DENSE_SAVED10 --battery "C:/CM/battery.csv" --velocity "C:/CM/velocity.csv" --generator "C:/CM/generator.csv"
```

실행 프로젝트·로그가 있으면 `--project 경로 --log 경로`를 추가할 수 있다. 파일이 제공한 준비본과 바이트 단위로 같더라도 그 파일이 실제 실행됐다는 증명이 자동으로 생기는 것은 아니다. GUI 재저장으로 바이트가 달라진 경우도 즉시 잘못된 모델로 단정하지 않고 내용 대조 대상으로 표시한다.

`--confirm-unmodified`는 사용자가 실제로 수정 없이 실행했다고 확인했을 때만 쓴다. 결과 수치가 같다는 이유로 이 플래그를 추정해서 넣지 않는다. R0의 기존 사용자 확인은 이미 수용했다.

접수 자료는 내용 해시로 보존한다. 같은 시험에 같은 파일을 다시 접수하면 같은 접수 기록을 사용하며 새 실행으로 세지 않는다. 별도의 실제 반복 실행을 구분하려면 대응 실행 로그 등 별도 근거를 함께 보존한다. 원본 파일은 덮어쓰지 않는다.

## 무엇을 검사하는가

1. 신호명·단위·유한값·시간 순서·전체 구간·CSV 간 시간축 일치
2. 등록한 시험의 초기 SOC와 목표 속도 프로파일
3. 발전 OFF, 기대 보조부하, DC 전력 수지
4. 단자 전압×방전 양수 전류의 순에너지와 실측 기준 에너지
5. 전압·속도 오차와 감도, 세밀 출력의 같은 실행 내1초 적분 비교
6. 원본·기준자료·검토 결과가 변경됐는지 해시 검사

전압·속도 지표는 출력 간격 차이로 표본 가중치가 달라지지 않도록 공통1초 격자에서 계산한다. 에너지는 각 CSV의 실제 저장 시각에서 계산한다. 기존20초–각 시험 종료 평가창을 유지한다. 기존 정확도 목표는 에너지±5%, 전압 RMSE2V, 전압 편향±1V, 속도 RMSE1km/h다. 원인 비중이나 최종 보정값을 자동으로 만들지 않는다.

## 상태와 판정

- 준비본 등록: 해시·시험 조건을 등록한 상태. 실제 실행 완료가 아님.
- CSV 접수: 파일을 보존한 상태. 정상 자료라는 뜻이 아님.
- VALIDATED_EXPORT: 신호·시간창·단위 등의 자료 검사를 통과한 상태.
- 프로토콜 점검: 발전 정지·보조부하·전력 수지 등을 별도 확인.
- 정확도 목표: 실측과의 오차 기준. 자료 검사 통과와 구분.
- 실행 로그: 계산 종료·시계열 저장 메시지가 있어도 fatal 오류가 있으면 실패를 별도로 기록.
- 모델 채택: 사용자·연구자 판단. 자동 채택하지 않음.

실제 세밀 CSV가 없는 SAVED10/SAVED1은 계속 대기 상태다. 과거 CSV나 기대 파형으로 완료 상태를 만들지 않는다. 출력 적분 점검을 통과해도 solver 시간간격 수렴·저SOC·온도·실제 발전계까지 검증됐다고 말하지 않는다.

## 분석과 이력

등록한 오프라인 분석은 공개 배터리 전류 재계산, SOC/용량 식별 가능성, CAN SOC 변화량, 시간 정렬·회복, 전압·전류 에너지 산술 분해다. 코드는 원본을 격리된 임시 폴더에서 실행하고 산출물과 입력·코드 해시를 보존한다. 임의 파라미터 적합은 포함하지 않는다.

```text
python research.py analyze --stage timing_recovery
python research.py sensitivities
python -m unittest test_harness -v
```

검사 코드는 기존 지표 재현과 잘린 CSV·다른 시험 SOC·틀린 단위·출력 간격·전력 조건·자료 변조·저장 실패 로그의 거부를 확인한다. 검사에 쓴 과거 파일을 새로운 CRUISE 실행으로 세지 않는다.

registry.json은 시험 조건, policy.json은 판단 기준, recipes.json은 오프라인 분석 목록이다. assets_manifest.json으로 기준자료의 변경을 탐지한다. 기준·코드·정책을 변경할 때는 새 버전과 변경 이유를 기록하고 기존 접수·검토 결과를 보존한다. `bootstrap_history.py`는 최초 이관용이며 이미 구성된 하네스에서 재실행해 기록을 초기화하지 못하게 했다.

이 도구에는 CRUISE M 자동 실행이나 GitHub 게시 기능이 없다. 설치 버전의 실제 실행 인터페이스를 확인하기 전까지 자동 실행이 가능하다고 가정하지 않는다.
