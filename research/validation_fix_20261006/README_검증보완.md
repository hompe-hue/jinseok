# Bolt BEV / EREV 입력자료 검증 보완 — 2026-10-06

배터리 식과 구동계 맵의 입력 완료를 검증 완료로 취급하지 않도록, SOC 정의·자료 적용 범위·맵 생성 방식·시뮬레이션 판정 조건을 분리했다. 원자료의 계수와 기존 제어 규칙은 변경하지 않았다. ANL 원시 시험자료에 대한 오프라인 검산을 수행했으며, CRUISE M 프로젝트 실행 결과는 아직 없다.

## 1. 배터리 식의 SOC 단위와 정의

NREL/TP-5500-75323 Figure 12(파일 26쪽, 인쇄 1.20쪽)의 축은 SOC %. 이 그림의 계수에는 **퍼센트 s**를 넣는다.

- U(s) = 322.397 + 1.29836s − 0.0184756s² + 0.000143235s³ [V, 팩]
- R(s) = 0.0806969 − 0.000281326s + 0.00000166726s² [Ω, 팩]

CRUISE M에서 SOC를 **0–1 분율 z**로 받을 때는 다음의 등가식을 쓰거나 표의 `SOC_fraction` 열을 사용한다.

- U(z) = 322.397 + 129.836z − 184.756z² + 143.235z³
- R(z) = 0.0806969 − 0.0281326z + 0.0166726z²

본문의 일반식은 SOC 분율을 설명하지만, Figure 12는 퍼센트 축에 맞는 계수와 3차 OCV 식을 보여준다. 그림의 계수를 분율에 그대로 대입하는 오류를 막았다. 셀 입력은 96S3P 가정에서 Ucell = Upack/96, Rcell = Rpack×3/96이다. 두 개의 48S3P 모듈을 직렬 연결한다면 모듈 전압과 저항은 각각 팩의 절반이다. 같은 손실을 팩과 셀에 중복 입력하지 않는다.

표시 SOC, 내부 ECU SOC, 모델의 전류 적산 SOC는 서로 다른 정의다. NREL 보고서는 차량 CAN SOC를 사용했다고 설명하지만 Figure 12의 CAN 세부 채널이 ANL 표시/HPCM/HPCM2 중 무엇과 같은지는 확보한 문서에 명시하지 않는다. 따라서 이 식의 좌표를 ANL 표시 SOC 또는 화학적 SOC와 동일하다고 확정할 수 없다.

ANL 61905064의 표시 SOC 5.0973–79.9884% 구간에서는 다음 관측 관계를 얻었다. 표시 SOC 단계별 같은 가중치로 회귀했고, 시간 유지 행이 많은 구간이 과도하게 반영되지 않게 했다.

- HPCM2 SOC ≈ 0.939738 × 표시 SOC + 4.643163 [%], 잔차 RMSE 0.4040 percentage points.
- HPCM SOC ≈ 0.935836 × 표시 SOC + 4.626949 [%], 잔차 RMSE 0.3913 percentage points.

이는 **해당 시험의 채널 변환 후보**다. 80–100%, 다른 시험/차량, 화학적 SOC로 외삽하거나 BMS의 실제 변환식으로 사용하지 않는다. 예를 들어 시험 61905054는 표시 SOC 99.9855% 부근에서 HPCM2 96.824%, HPCM 96.432%를 보고한다. 두 내부 채널도 서로 같지 않다. 기존 S0~S4의 SOC 임계값은 유지하고, 향후 그 임계값이 어떤 SOC 좌표를 의미하는지 모델 문서에 고정한다.

## 2. 식의 유효 범위: 표 작성 범위와 검증 범위를 구분

0–100%는 식의 표 작성 범위다. Figure 12에는 저 SOC에서 큰 산포와 상단의 실측점 이후 다항식 연장이 보이지만, 원시 점별 SOC와 명시적 통계 유효 구간이 공개된 그림에는 없다. 그래프 축 끝을 곧바로 검증된 범위로 선언하지 않는다.

**5–95%는 이번 재검산과 후속 검증의 우선 구간으로 정한 연구 범위이며, NREL이 인증한 유효 구간이 아니다.** 현재 방전용으로 통과 판정을 내릴 수 있는 전체 SOC 구간은 확정하지 못했다. 0–5%, 5–10%, 95–100%는 따로 기록한다. 실제 EREV 제어 임계값 6–8%가 포함된 저 SOC 구간도 별도 방전 검증이 필요하다.

시험 Phase 1 인덱스는 원시 TDMS 메타데이터를 사용했다. 계측기 시간과 CAN 시간을 따로 정리하고, 중복 시간은 중위수로 통합했다. CAN SOC는 시간 정렬 후 이전 관측값을 유지했다. 2초를 넘는 간격이나 전압 200–450 V 밖의 구간을 조용히 이어 적분하지 않았다. 이 전압 필터는 계측자료 정리 조건이며 BMS 제한을 식별한 값이 아니다.

| 시험 / SOC 채널 | 검사 SOC 구간 | 팩 전압 RMSE | 판단 |
|---|---|---:|---|
| 61905065 충전 / 표시 | 5–95% | 1.839 V | 충전 조건에서의 참조식 재현 정도; 독립 CRUISE 검증 아님 |
| 61905064 방전 / 표시 | 5–95% 중 실제 관측 ~5–80.77% | 7.413 V | 방전 적용 통과로 선언 불가 |
| 61905064 방전 / HPCM2 | 5–95% 중 실제 관측 ~5–79.97% | 10.025 V | 채널만 바꿔도 해결되지 않음 |
| 61905054 주행 / 표시 | 실제 98.025–99.9855% | 13.829 V | 높은 표시 SOC 영역의 별도 모델 필요성을 보여줌 |

방전 61905064의 HPCM2 SOC 5–10% 구간 전압 RMSE는 약 21.30 V이다. 동일 R을 충전과 방전에 적용하고 RC/온도/히스테리시스를 생략한 현재 참조 모델은 저 SOC 제어 검증에 충분하지 않다. 공개 데이터의 표본 수는 독립 시험 횟수가 아니며, 시계열 점들을 독립 반복시험처럼 해석하지 않는다.

61905064의 선택 구간은 계측기 Phase 시간의 100%, 61905065는 약 53.54%였다. 방전 말단 275.77–279.99 V의 353개 행을 이전 280 V 필터가 제외했음을 확인하고 이번 최종 계산에서는 포함했다. 이 구간을 계측 오류나 BMS 제한 위반으로 간주하지 않았다. 계측기 시간과 Phase 메타데이터의 기준 시간도 약간 다르므로, 적분 시간과 메타데이터 시간을 따로 기록했다. 충전 시험은 전압이 유효한 구간에서 실제 충전 에너지를 포함하지만 충전 이후 무효 계측 구간이 길다. 필터 적용 적분과 시험 메타데이터의 총량도 구분했다. 방전 유효 구간 적분 46.773 kWh는 메타데이터 46.903 kWh와 같지 않으며 누락/측정 처리 차이를 기록해야 한다. 61905064의 메타데이터 거리 180.521 mi는 해당 시험의 거리이고 EPA 라벨 주행거리가 아니다.

168 Ah(셀 56 Ah)는 아직 가정이다. 같은 전류 적분에서 채널 SOC 변화로 계산한 겉보기 용량은 방전 표시 채널 약 171.02 Ah, HPCM2 약 181.75 Ah였다. 높은 표시 SOC만 관측한 61905054에서는 약 280.07 Ah로 왜곡된다. 이 수치들은 유효/화학 용량의 측정값이 아니며, 표시 SOC가 적산 전하에 전 구간에서 일정 비례한다고 가정할 수 없음을 보여준다. 168 Ah를 쓴 방전 표시 SOC 적산은 말단에 약 −0.65%를 예측한다. 0%로 자르는 처리는 용량/SOC 불일치를 숨기므로 검증 중 사용하지 않는다.

참조식 U(100%)=410.712 V이고, 기존 연구 가정 Vmax=403.2 V(96×4.2 V)를 약 95.828%부터 초과한다. 이 가정 제한은 식과 함께 모순 없이 재설정/식별해야 한다. SOC를 95.828%로 자동 제한하면 가용에너지와 주행거리도 바뀌므로 기존 입력을 임의로 수정하지 않았다.

### 배터리 적용 순서

1. CRUISE 배터리 SOC는 모델의 전류 적산 분율로 정의하고, 비교용 표시/내부 SOC는 별도 출력 또는 변환 채널로 둔다. NREL CAN 좌표와의 대응이 확인되기 전에는 초기 참조 모델로 표기한다.
2. 원시 전류 입력 재생으로 V, SOC, DC 에너지와 말단 오차를 확인한다. 단순 전압 오프셋으로 공식 주행거리를 맞추지 않는다.
3. 방전 저 SOC와 높은 SOC 오차를 줄이기 위해 방전 방향의 OCV/R 또는 RC 모델을 식별한다. SOC·전류·온도의 충분한 자극을 확인하고, 적합에 사용하지 않은 별도 시험에서 재검증한다. 현재 세 시험은 온도/방향/SOC가 서로 달라 단일 전 구간 식별을 충분히 지지하지 않는다.
4. 예시 연구 기준은 전압 RMSE≤2 V 및 |평균 편향|≤1 V, SOC 말단 오차≤2 percentage points, DC 에너지 오차≤5%이다. 공인 기준이 아니며 교수님과 **시뮬레이션 전에** 확정한다. 현재 방전 참조식은 이 예시 기준을 통과하지 못한다.

## 3. 완성 구동계 맵의 보간·외삽·회생 추정 기록

사용 자료는 EPA의 **2018 Chevrolet Bolt 150 kW / 400 V FWD EDU** 완성맵이다. EDU는 모터·인버터·기어 손실을 함께 포함한다. 이를 등가 E-Motor 손실맵에 넣으면 별도 인버터 손실과 기어 효율 손실을 중복 부과하지 않는다. 기어비 7.05와 등가 축의 속도·토크 좌표를 일치시킨다. ANL 2017년형 차량에 2018년형 EDU 자료를 사용하는 것은 연식 간 이전 가정이며 실차 전체 동등성이 확인된 것은 아니다.

EPA 생성 설명서에는 측정점 정리, 경계 부근의 보완점 추가 가능성, 구동 사분면 손실 공간에서의 경계 외삽 및 최대출력 스케일링을 설명한다. 각 보완점/외삽점의 원시 계보는 완성맵만으로 복원할 수 없다. 따라서 볼록껍질 안이라고 해서 직접 실측 격자점이라고 표시하지 않았다.

| 분류 | 전체 격자점 | 운전 한계 안 |
|---|---:|---:|
| 실측점 볼록껍질 안의 완성맵 | 64 | 63 |
| 볼록껍질 밖의 완성맵 | 44 | 18 |
| 회생 추정 영역 | 96 | 70 |
| 합계 | 204 | 151 |

252개 원측정점은 회생 실측을 포함하지 않는다. EPA는 구동 손실을 회생 사분면으로 반영하면서 **1.05배** 손실 계수를 사용했다. 이는 회생 효율을 1.05배 한 것이 아니다. 원측정점에서 완성맵을 보간한 손실 RMSE 0.093604 kW는 원자료 재구성 검사이며 독립 실차/CRUISE 검증 지표가 아니다.

운전 허용 여부는 표 존재 여부와 별개다. 실제 점에서 Full load 토크 한계, |축출력|≤150 kW, 0–8250 rpm, 표의 속도·토크 축을 모두 확인한다. 표 바깥 외삽은 금지하고 위반한 요청점/실제점을 기록한다. Full load 안의 점이라도 보간에 사용하는 모서리 격자점에 외삽·회생 추정·Full load 밖 자료가 포함될 수 있으므로 검사 도구가 그 개수도 기록한다.

CRUISE 조회 정책은 **손실 kW의 쌍선형 보간**이다. Pshaft=2πnT/60, PDC=Pshaft+Ploss이며 모터 축출력이 양수인 구동과 음수인 회생을 같은 부호 체계로 유지한다. 전기출력이 양수인 낮은 속도의 음의 토크는 순수한 회수 발전이 아니다. 0 rpm 또는 0 torque에서 효율을 나누어 계산하지 않고 손실값을 사용한다. CRUISE 컴포넌트의 보간 설정이 실제로 이 정책과 같은지는 입력 후 확인해야 한다.

400 V 단일 전압 맵은 전압/온도 변화에 대한 측정 맵이 아니다. 실제 팩 전압 범위와 이 단일 맵 적용 가정을 기록한다. 회생 손실 계수 1.00/1.05/1.10의 후보표를 제공했으며 각각 별도 시뮬레이션으로 DC 전비·회수에너지·SOC 변화·거리 변화를 비교한다. 이 세 값은 연구 민감도 시나리오이며 통계 신뢰구간이 아니다.

## 4. CRUISE M 검증 및 연구 진행 기준

중간 보고의 목적은 **선정한 Bolt BEV 모델이 명시한 시험 조건에서 공개 실험을 얼마나 재현하는지** 확인하는 것이다. 한 모델의 일치로 CRUISE M 전체가 검증되었다고 결론 내리지 않는다.

먼저 ANL 시험의 시간·시험 질량·도로부하·보조부하·초기 상태를 맞춰 속도 추종, 배터리 V/I/SOC, DC 소비에너지와 회생에너지를 비교한다. 모델의 저장 SOC와 표시 SOC 비교를 혼합하지 않는다. 참조식 식별 데이터와 최종 판정 데이터를 분리한다. 결과 CSV와 프로젝트, 컴포넌트 설정, 실행 로그를 함께 남긴다.

EPA 라벨 전비는 벽전원 AC 및 충전 손실을 포함하므로 배터리 DC 전비와 직접 동등 비교하지 않는다. 주행거리도 해당 시험/라벨 조정 절차를 맞춰 비교한다. EPA는 일반적인 0.7 조정과 조정 후 시내/고속 55/45 가중을 설명하지만, 이를 결과를 맞추기 위한 임의의 보정 계수로 쓰지 않는다. 적용 절차를 재현하지 못하면 공식 주행거리는 참고값이고 동등조건 검증값은 아니다.

중간 보고 이후 EREV에서는 검증된 BEV 구동계를 고정한 뒤 엔진·발전기·전력 변환기·연료·열/시동 제어를 추가한다. 기존 주 연구의 26 kW 순발전 기준과 제어 S0~S4는 유지한다. 1.5 L/80 kW 엔진 및 순발전 65 kW의 스케일링 후보는 별도 설계 가정이며 이번 검증 보완으로 실제 정격/실측 맵이 된 것이 아니다. 엔진 연료맵과 발전기 맵의 조건·전압·Full load를 교차 확인한다.

### 연료소비 / 총 주행거리 비교 조건

- 연료유량 g/s를 시간 적분하면 kg이다. L 비교는 사용 연료 밀도를 기록한다. 냉시동·워밍업·아이들·재시동 연료가 없으면 따뜻한 정상상태 가정의 연료 결과로 한정한다.
- 전략 간 차량/엔진/발전기/연료맵/주행 사이클/온도/보조부하가 같아야 한다. 초기뿐 아니라 **최종 배터리 저장에너지**도 맞춘다. 기본 비교 허용차 0.1 kWh는 변경 가능한 연구 설정이다. 말단 에너지가 다른 경우 유리한 연료 수치를 그대로 비교하지 않으며 임의의 등가연료 보정도 적용하지 않는다.
- 총 주행거리는 초기 배터리 에너지와 연료 질량, 배터리 SOC/전압 하한, 연료 고갈, 지속 가능한 출력 및 속도 추종 실패의 종료 규칙을 선언한 반복 임무에서 계산한다. 고정 사이클을 완주한 거리는 총 고갈 주행거리와 구분한다.
- 아직 실제 EREV 연료소비·총 주행거리와 실제 CRUISE BEV 검증 통과 결과는 산출하지 않았다. 관련 입력표·판정 규칙·출력 분석 도구가 준비되었고 템플릿은 미검증 상태로 잠겨 있다.

## 5. 파일 사용

- `Bolt_Validation_Inputs_and_Audit_20261006.xlsx`: SOC 정의, 계수 표, 전압 잔차, 시험별 품질, 맵 점별 계보/한계, 회생 민감도, 판정 기준.
- `inputs/battery_reference_with_validity.csv`: 기존 참조식과 검증 상태. 기존 파일을 자동 교체하지 않는다.
- `inputs/bolt_map_provenance_and_limits.csv`: 각 격자점의 실측 지원/회생 추정/운전 허용 분류.
- `inputs/bolt_regen_sensitivity_LOSS_kW.csv`: 손실 단위 kW, 회생 계수별 후보. 실제 입력은 해당 계수 열로 개별 표를 만든다.
- `inputs/cruise_trace_template.csv`, `inputs/trace_metadata_template.json`: 실제 출력과 비교 조건 기입용. 예시 결과 행을 실제 결과로 넣지 않았다.
- `scripts/evaluate_cruise_trace.py`: 실제 출력 CSV의 축/Full load/전비/연료/말단 에너지 검사. 비교 준비 여부는 입력 선언과 수치 일관성 검사이며 실행이나 검증 로그의 진위를 자동 확인하지 않는다.
- `scripts/check_evaluator.py`: 단위, 범위와 비교 거절 조건을 확인하는 합성 검사. CRUISE 실차 검증이 아니다.
- `Bolt_Validation_Audit.ipynb`: 실행 완료한 분석과 근거. 원시 CSV·TDMS·NREL PDF는 별도 공개자료 압축에 있으며 소스 해시를 기록했다.

재현 명령(패키지 루트에서; source와 raw 경로는 자료가 있는 위치로 변경):

```bash
python scripts/audit_inputs.py --source ../validation_sources/public_inputs/Bolt_CRUISE_M_DataKit --raw ../validation_sources/raw_reference/raw_tdms
python scripts/check_evaluator.py
python scripts/evaluate_cruise_trace.py YOUR_ACTUAL_TRACE.csv YOUR_METADATA.json --output YOUR_AUDIT.json
```

의존성은 numpy, pandas, scipy, nptdms이다. 노트북 실행에는 nbformat, nbclient, ipykernel이 추가로 필요하다. sources 해시는 `inputs/source_hashes.json` 및 `raw_source_hashes.json`에 있다. 무효 구간을 복구하려면 원시 자료의 계측 채널과 계측기 설정을 확인하고 변경 내역을 따로 보존한다.
